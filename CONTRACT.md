# Core and CLI contract

## Observable behavior

`swift-crap analyze --project ROOT --coverage LLVM.json [--coverage OTHER.json] [--format json|text] [--threshold 30]` inventories production Swift beneath ROOT and evaluates CRAP(line)-v1. Alternative mutually exclusive selectors: `--package DIR`; `--package DIR --target NAME`; `--file PATH`. `--root ROOT` provides stable project identity for package/file scopes. `--sources-manifest FILE --target NAME` selects explicit target paths for build systems such as Xcode. A source manifest has `{ "root": ".", "targets": { "App": ["Sources/App.swift", "Sources/Feature"] } }`; root is relative to the manifest file. `--exclude RELATIVE_PREFIX` repeats. Exclusions are path-component prefixes under root, never arbitrary substring matches. Repeated `--coverage` auto-detects LLVM and xccov JSON. `--missing error|zero` defaults to error; zero is an explicit assumption and is labeled. Default threshold is 30, failure means strictly greater than threshold. `--format json` uses schemaVersion 1 and metric `crap-line-v1`, ordered by relative file then start position then ID. JSON has functions and summary with counts. `--baseline FILE` compares IDs only under identical metric semantics and rejects duplicate IDs or incompatible schemas. With a baseline, any score increase for an existing ID fails, including increases below the absolute threshold; unchanged or improved existing scores pass, and new functions must satisfy the threshold. Exit 0 clean, 1 invalid input/analysis failure, 2 gate failure. Help and version exit 0. No usable sources or zero callable inventory is an error. `analyze` only reads source/build metadata and coverage; never runs tests itself. CLI analysis requires `--provenance RECEIPT` unless `--trust-coverage unverified` is explicit. `capture` is a separate, explicitly requested command that runs a build/test workflow and records source/artifact fingerprints plus compiler-aware inventory; see docs/readiness-contract.md and docs/provenance.md.

Project discovery skips .git, .build, .swiftpm, Packages checkouts, DerivedData, Tests, test fixtures, and hidden folders; package mode uses `swift package describe --type json` metadata, excluding test/plugin/binary/system targets. Target lookup errors on absence or ambiguity. SwiftPM describes only the selected package. Xcode target membership uses the resolved `xcodebuild -showBuildSettingsForIndex -json` graph via `--xcode-project PATH --scheme NAME --target NAME`, with explicit configuration/destination. Captured Xcode analysis reuses that membership and rejects a different configuration. Custom build systems can use an explicit sources manifest; never guess target membership from directory names. File scope includes that file regardless of test-directory naming; root defaults to its parent. Project mode analyzes all selected production paths even if they lack coverage, making missing instrumentation explicit. Symlinks must not escape root. Sort/deduplicate files.

## Shared public types (owner: root)

All below belong in CrapCore, Codable/Equatable/Sendable where appropriate. Coordinates use positive one-based line and UTF-8 byte column. SourceSpan is half-open.

`SourcePosition(line: Int, column: Int): Comparable`

`SourceSpan(start: SourcePosition, end: SourcePosition)` with `contains(_ position: SourcePosition) -> Bool`.

`CallableKind: String` cases function, initializer, deinitializer, getter, setter, observer, subscriptGetter, subscriptSetter, closure.

`Callable(id: String, file: String, name: String, kind: CallableKind, span: SourceSpan, bodySpan: SourceSpan, complexity: Int, parentID: String?)`. File is normalized root-relative with slash separators; name is qualified full signature; id includes file/name/kind/signature and lexical identity for anonymous closures. Source positions do not belong in named function IDs. Generic constraints and parameter types must distinguish overloads. Complexity starts at 1; count if/guard/for/while/repeat/catch, non-default switch cases, &&/||/ternary/??, comma-separated conditions, for-where. Skip nested callable bodies when counting parent. Define rules in docs and lock down tests. No alternate switch-discount metric. Build-aware capture evaluates `#if` with SwiftIfConfig and a compiler-backed build configuration. Both inventory and complexity traverse only active regions while preserving original source positions. Unknown conditions and invalid active syntax fail. The parameterless library analyzer and explicitly unverified CLI imports inventory all branches. Invalid syntax is an analysis error. Declarations generated by macros are outside authored source inventory; written macro arguments/closures remain traversable. Distinguish implicit getter bodies and property observers.

`CoverageLine(line: Int, covered: Bool)`

`CoverageRecord(file: String, name: String, span: SourceSpan?, anchor: SourcePosition, lines: [CoverageLine]?, coveredLines: Int?, executableLines: Int?)`. Import adapters output canonical absolute paths if inputs absolute, otherwise preserve relative; engine reconciles through root. LLVM uses function records and their source regions, not file-global line coverage. xccov uses aggregate counts and anchor, with column 1 when unspecified. xccov closures must not be mistaken for parents. Multiple observations of identical owned lines union execution. If only aggregates exist and multiple nonidentical observations cannot be correctly unioned, fail rather than average/max fractions. Decoder validates counts and positions and rejects unsupported schema/malformed structures.

`CoverageImport(records: [CoverageRecord], format: String)`

`SourceAnalyzing` capability: `func analyze(source: String, file: String) throws -> [Callable]`

`CoverageDecoding` capability: `func decode(_ data: Data) throws -> CoverageImport`

`MissingCoveragePolicy: String` error, zero.

`FunctionScore(callable: Callable, coveredLines: Int, executableLines: Int, coverage: Double, crap: Double, coverageStatus: String)` where status measured or assumedZero. Engine must reject nonpositive/invalid complexity and ambiguous source/coverage joins. Missing zero entries have counts 0/0, ratio 0, clearly assumed.

`AnalysisReport(schemaVersion: Int = 1, metric: String = "crap-line-v1", functions: [FunctionScore], summary: ReportSummary, verification: String? = nil, buildIdentity: String? = nil)`; CLI verification is captured or unverified, absent for an unverified library caller. Captured CLI analysis requires a captured baseline with the same nonempty build identity. Identity binds the canonical root, exact selection/exclusions and compiler contexts, not source inventories or output artifacts; it is conservative and machine-local. Baseline bytes are read once, validated and reused. Summary includes totalFunctions, measuredFunctions, assumedFunctions, violations and threshold. Stable synthesized Codable keys are contract.

`AnalysisEngine` initializer empty; `analyze(callables: [Callable], coverage: [CoverageRecord], root: String, missing: MissingCoveragePolicy, threshold: Double, baseline: AnalysisReport? = nil) throws -> AnalysisReport`. Engine owns reconciliation, formula, validation, ordering, baseline, gate decisions. Report summary.violations reflects actual baseline-aware gate violations. Reject threshold NaN/infinite/negative.

Root owns shared types; implementation agents must not modify shared types without coordinating. Additional private/internal types allowed in one type per file. Core tests may import public engine; syntax tests public analyzer; coverage tests public decoder. Public adapter names `SwiftSourceAnalyzer: SourceAnalyzing` and `CompilerCoverageDecoder: CoverageDecoding`.

## Black-box verification

Unit tests define exact scores, decision counts, callable isolation, identity and invalid inputs. Integration tests compile tiny independent Swift fixtures using swiftc with -profile-generate -profile-coverage-mapping, execute them, merge via llvm-profdata, export via llvm-cov, and join with real source analysis. Include full/partial/zero coverage, nested/one-line callables, and complementary input coverage. E2E tests launch the built executable and assert JSON, scope selection, deterministic bytes, exit codes, package custom source paths, explicit target manifest, malformed coverage, missing coverage, baselines, paths with spaces and no mutation. Tests assert observable outcomes rather than private helpers. Core tests should run on macOS/Linux; Apple toolchain integration is tested on macOS and portable where LLVM tools exist.
